# Product discovery and pilot design

## Interview an applicant / reviewer

Ask for a recent submission journey, where information was missing, how deficiencies were communicated, who prepared supporting analysis, what tools were used, and what a useful handoff looks like. Ask to observe an anonymized case with permission. Measure preparation and review time separately. Do not optimize only for the applicant if a longer machine-generated package burdens reviewers.

## Interview an estimator / sustainability lead

Ask which drawing formats and revisions they actually receive, which assemblies dominate effort, how quantities are checked, what changes across plan families, where factors come from, and what outputs customers request. Ask for a reference takeoff and a correction session. A convincing carbon chart cannot compensate for unreliable quantities.

## Pilot agreement outline

Specify inputs, authorized users, data ownership, permitted cloud processors, retention/deletion, allowed public examples, task boundaries, expert reviewers, success measures, issue escalation, and export formats. Define whether the pilot informs a decision or produces an official deliverable. Agree who can accept corrected facts and how later revisions are handled.

## Commercial hypotheses to test

Codes: paid preparation workflow, consultant workspace, reviewer triage tool, or enterprise knowledge integration. Carbon: per-plan assessment workflow, portfolio plan-family management, factor-management service, or estimator copilot. These are hypotheses, not confirmed demand.

For each, record buyer, daily user, procurement path, current cost, willingness-to-pay evidence, expected frequency and switching friction. Calculate cost per completed case: parsing + model calls + factor access + storage + human review + support. Price a reliable workflow rather than a token count.

## Suggested backlog by maturity

Prototype: one useful case, corrections, sources, and tests. Pilot: access controls, revision history, dataset permissions, cost monitoring and failure recovery. Production: formal domain validation, support, security assessment, operational monitoring, retention enforcement, and a documented responsibility model.
