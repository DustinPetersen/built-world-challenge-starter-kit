# Office-hours mentor playbook

For this event, use the [Edmonton mentor questions](../edmonton/mentor-questions.md) alongside this facilitation guide.

## A 20-minute conversation

| Time | Activity | Leave behind |
| --- | --- | --- |
| 0–3 min | Ask who uses it, what they do today, and what input is available | One user and one problem |
| 3–7 min | Walk through an actual or synthetic example | Input → review → useful output |
| 7–12 min | Find the highest-risk assumption | One experiment that could disprove it |
| 12–17 min | Cut scope and divide work | Three tasks with owners |
| 17–20 min | Define demo success and next check-in | Three acceptance cases |

## Questions that unlock progress

- What can your user do after this that they cannot do now?
- Which step needs AI, and which can be a table lookup or calculation?
- Can you show the original evidence for this output?
- What happens when the input is missing, ambiguous, or wrong?
- What can a user correct, and does everything downstream update?
- What will you test on an input the developer has never seen?
- Which assumption requires an industry expert rather than more coding?

## Challenge-specific pressure tests

Codes: Which jurisdiction, edition, and form? Who verifies applicability? Can an invented citation slip through? Does a populated field get mistaken for adequate evidence? Where does professional judgment enter?

Carbon: What is the measurement basis? Can quantities be reconciled with factor units? Which assemblies are missing? Is the source a product EPD or an average? What happens when an EPD is expired? Is the total explicitly partial?

## Two-hour volunteer block

Spend 10 minutes orienting with the event team, four 20-minute sessions with teams, 20 minutes reviewing a shared failure pattern, and 10 minutes leaving written next steps. Adapt to demand. Ask permission before sharing team examples publicly.

Record: team / user / blocker / decision / next experiment / owner / follow-up. Encourage teams to own their decisions; avoid introducing a new framework when the bottleneck is missing data.
