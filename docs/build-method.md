# Build method

This is a suggested plan, not the event timetable.

## A five-hour build session

1. **First 30 minutes:** choose one user; inspect an input; write the output by hand. Confirm rights to use the data.
2. **Next 30 minutes:** write three acceptance cases, a data contract, and the most likely failure. Make an end-to-end skeleton with synthetic data.
3. **Next 90 minutes:** implement the riskiest slice. Codes: evidence-backed checklist. Carbon: reviewed geometry and units.
4. **Next 60 minutes:** add corrections, provenance, and explicit missing-data states.
5. **Next 45 minutes:** evaluate unseen and deliberately broken inputs; record failures.
6. **Final 45 minutes:** rehearse a three-minute demo, show a failure, and state the next validation step.

## Suggested eight-week progression

| Stage | Evidence to obtain |
| --- | --- |
| Weeks 1–2: understand | Three user interviews, approved sample inputs, manually produced reference outputs |
| Weeks 3–4: build | One narrow end-to-end workflow and repeatable evaluation |
| Weeks 5–6: test | Unseen cases, reviewer feedback, timing and error measurements |
| Weeks 7–8: pilot plan | Operating cost estimate, privacy plan, clear handoff, commercial hypothesis |

## Scope cuts

Prefer one jurisdiction over all Canada; one assembly over an entire house; one validated retrieval corpus over unrestricted web search; one corrected revision over live collaboration. Treat these as prototype boundaries and document the path to broader scope.

## Definition of done

A new teammate can run the demo; every important output has a source or assumption; missing evidence is visible; edits recalculate derived results; tests include a refusal or unresolved case; no private source material or secrets are committed.
