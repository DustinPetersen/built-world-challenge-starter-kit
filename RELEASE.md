# Expanded release — October 2026

## Scope delivered

The kit covers both event challenges through starter ideas, worked specs, technical stacks, AI/extraction methods, integration candidates, real licensed housing-context data, synthetic fixtures, evaluation, mentorship, product discovery and publishing guidance. One repository keeps the entry point simple; a documented split strategy supports later independent data or application repos.

## Read the evidence at the appropriate level

- API catalog: 50 curated services, libraries, tools and reference hubs. Official documentation was reviewed. This is not a claim that 50 authenticated APIs were tested.
- NRCan data: three original CSV tables with 6,794 rows each (256, 85 and 199 columns respectively). These tables relate to the same archetype library and must not be described as 20,382 independent homes. Original license, upstream README, pinned commit and hashes are included.
- Synthetic data: 60 slab geometry cases and SVG diagrams; 20 manual failure scenarios. These are not sponsor plans or real-world accuracy evidence.
- Code: offline carbon arithmetic, illustrative application presence checks, housing-table summary, and optional read-only Canadian catalog discovery.
- Validation: unit tests cover arithmetic corrections/substitutions/rejections, catalog consistency, synthetic geometry/diagram validity, and upstream file integrity/table shapes. Manual scenarios and proposed acceptance criteria are future implementation targets.

## Important remaining external dependencies

Real challenge implementation still needs organizer-approved plan sets and reference takeoffs, the exact forms/checklists and code corpus, domain review, and any chosen vendor credentials/agreements. Linked EPD data is not bundled because API access and redistribution rights need separate confirmation. The resource hub is maintained at https://github.com/DustinPetersen/built-world-challenge-starter-kit. No vendor account was created.

## Maintenance

Treat this as a broad, dated reference release rather than a permanently exhaustive inventory. Recheck links, licenses, editions, processor limits and account entitlements before implementation. Contribute newly verified sources through the issue template. Preserve the distinction between official requirements, proposed approaches, synthetic fixtures and observed test results.
